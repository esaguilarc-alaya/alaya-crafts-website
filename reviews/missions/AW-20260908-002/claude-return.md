## Deviations, uncertainty, and unproved items
- **CSS selector collision (self-caught and fixed before commit):** my first implementation used bare class selectors (`.practice{left:...;top:...}` etc.) matching the pre-1.0 pattern already used for `.capability`/`.knowledge`. `.practice` collides with the pre-existing `<section class="section practice">` (Section 04's outer section element), which already had `position:relative` from the global `.section` rule — adding `left`/`top` shifted that entire section 56% to the right, blowing out `document.documentElement.scrollWidth` to 2246px at 1440px and 410px at 390px. Caught by the pre-existing `scrollWidth` regression tests (`Homepage uses the shared route contract`, `real 390px viewport has no overflow…`, and the Section 05/07 390px test) before this return was written. Fixed by scoping every new/kept label selector to `.field-label.<name>` and adding a `max-width` to the base rule. Full suite is green in both modes after the fix; this is recorded here rather than silently, per the no-silent-remediation control.
- **Content-credential (C2PA) metadata removed rather than carried forward:** the two Section 05 SVGs carried an embedded C2PA manifest (base64 CBOR, cryptographically signed) asserting file identity/provenance for the prior byte-identical asset. The packet explicitly instructs not to carry forward metadata that would falsely claim an altered asset is byte-identical to or authenticated as the prior input. Since I have no means to produce a valid replacement signature for the revised bytes, I removed the manifest and the `xmlns:c2pa` attribute entirely rather than leave a stale/misleading credential attached to changed content. This did not require stopping under the packet's provenance-conflict stop condition, because removing the metadata (rather than being forced to preserve it) fully resolves the conflict. Visible rendering is unaffected (the manifest was non-visual `<metadata>`).
- **Label position values are restrained-judgment placements, not exact pixel-to-concept mappings:** as the original 4-label design already did (percentage positions approximating, not exactly tracing, terrain/path features), the six new positions were chosen to sit near existing path nodes and terrain features and were verified visually (screenshots at both required viewports, plus the automated per-label bounding-box containment tests) rather than derived from an exact geometric mapping. This is within the "bounded compositional judgment for responsive label placement" the packet grants.
